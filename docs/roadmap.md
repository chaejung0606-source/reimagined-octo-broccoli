`~/.claim-downloader/_화면구조.txt` 로 저장한다. **읽기만. 아무것도 클릭하거나 값을 넣지 않는다.**

  (브라우저가 열려 있을 때), 콘솔은 `python -m claim_downloader --structure`.
- 비밀번호·파일 칸의 값은 남기지 않고(값을 읽는 칸 종류 허용 목록), 다른 값도 40자에서 자른다.
  결과 파일은 저장소·배포 zip 에서 제외. `tests/test_safety.py` 가 이 JS 가 읽기만 하는지 본다.
- 모의 결의서내역 화면으로 검증: 결의서 목록 프레임을 알아보고 `#btnDetail` · 행 체크박스가 나온다.
  **실제 ERP 결의서내역에서 CLAUDE.md 6절과 같은 결과가 나오는지는 담당자가 한 번 돌려 확인한다.**

## 2. 일반청구 (실측 → 설계 → 입력만 자동 → 제출은 사람)

1. **실측** — 완료 (2026-10-13, CLAUDE.md 14절): 프레임 `rexpe_0084_01.act`, 입력 필드 id, 저장·신청은 id 없는
   글자 링크라 금지 목록은 글자로. 입금처 돋보기 팝업·첨부 팝업·비목별로 열리는 블록은 미실측("(추정)").
2. **설계** (코드 전에, 담당자 확인 받고):
   - 입력 자료: 예) 엑셀 한 행 = 청구 1건. 열: 적요 / 금액 / 비목 / 입금처 / 계좌 / 증빙파일 경로
   - 흐름: 자료 읽기 → 화면 열기 → 필드 채우기 → 화면에 요약(건수·총액·각 건의 적요/금액/입금처) → 멈춤
   - 저장·신청·제출은 코드가 절대 누르지 않는다. 사람이 브라우저에서 눈으로 확인하고 직접 누른다.
   - 단계별 로그, 실패 시 멈추는 위치, 같은 건을 두 번 입력하지 않는 입력 기록.
3. **구현 (dry-run 이 기본)**: 필드를 채우고 요약을 보여 준 뒤 멈춘다. 1건만 처리하는 옵션.
   `tests/test_safety.py` 의 금지 목록에 제출 계열 버튼 id 를 더한다. 받기 기능은 건드리지 않는다.
4. **안정화**: 1건 → 3건 순서로 시험. 제출은 계속 사람이 한다. 3건 연속 정상이면 실제 업무에 사용.
