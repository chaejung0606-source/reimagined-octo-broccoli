# 04. 앱 아키텍처 제안

## 1. 사용자 흐름

```
① 지출종류 선택          근로장학금(TA형/서포터즈형) · 혁신인재지원금 · 출장비
        ↓
② 서류 업로드            폴더 통째로 드래그 (zip 포함) — 파일 개수 제한 없음
        ↓
③ 문서 자동 분류         파일명 + 첫 페이지 특징으로 서류 종류 판정
        ↓                 └ 애매하면 사용자에게 "이 파일은 무엇인가요?" 확인
④ 필드 추출              텍스트 / 표 / OCR / Vision 4단 파이프라인
        ↓
⑤ 규칙 평가              rules/*.yaml 을 순차 적용
        ↓
⑥ 결과 화면              🔴 수정 필요 / 🟡 확인 요망 / 🔵 판독 불가 / 🟢 이상 없음
                          항목마다 [근거 · 검출값 · 조치] + 원본 위치로 점프
        ↓
⑦ 내보내기               수정 요청서(PDF·엑셀) 출력 → 제출자에게 그대로 전달
```

**⑦이 이 앱의 실질적 산출물입니다.** 담당자가 "이거 이거 고쳐서 다시 주세요" 를
손으로 쓰는 시간을 없애는 게 목적이므로, 조치 문구는 **그대로 복사해 보낼 수 있는 완결된 문장**이어야 합니다.

## 2. 문서 자동 분류 (③)

파일명이 자유롭기 때문에 파일명만으로는 부족합니다. 2단계로 판정합니다.

```
1차: 파일명 키워드          "근무상황부" / "출장신청서" / "지급내역" / "기본정보" …
2차: 첫 페이지 텍스트 지문   "[양식5]" / "국내 출장신청서" / "* 체류 증빙" / "하이패스는"
3차: 둘 다 실패 → 사용자 확인 (드롭다운)
```

샘플에서 확인된 지문:

| 서류 | 지문 |
|---|---|
| 근무상황부 | `근로장학생 근무상황부`, `[양식5]`, `[붙임1]` |
| 출장신청서 | `국내 출장신청서`, `다음과 같이 출장을 명함`, `실사구시` |
| 출장증빙 | `* 교통비 증빙`, `* 이동경로`, `* 체류 증빙` |
| 하이패스 | `하이패스는`, `입구영업소`, `한국도로공사` |
| 카드전표 | `승인번호`, `사업자등록번호`, `가맹점명` |
| 지급내역 | `지급내역`, `연번`, `합   계` |
| 개인정보 동의서 | `개인정보 수집 ․ 이용 동의서` |
| 혁신인재 신청서 | `[양식8]`, `혁신인재지원금 신청서` |
| 활동보고서 | `[양식7-1]`, `월별 활동 결과 보고서` |

## 3. 추출 파이프라인 (④)

```
PDF ──┬─ 텍스트 레이어 있음? ─── yes ─→ pdfplumber (문단) + 좌표 기반 표 재조립
      │                                    ↓ 실패 시
      └─ no (스캔/이미지) ────────────→ 전처리(회전보정·이진화) → OCR
                                             ↓ 손글씨거나 OCR 저신뢰
                                          Vision LLM (구조화 JSON 출력)
```

주의할 실제 사례:

- **전자결재 PDF 일부가 헤더 손상** (`invalid pdf header: b'Handy'`).
  `이성재/국내 출장신청서 (3건).pdf` 는 표준 파서로 열리지 않습니다.
  → `pypdf(strict=False)` → 실패 시 `pypdfium2` 렌더 후 OCR 로 폴백.
- **표 셀 순서 뒤엉킴.** 지급내역·근무상황부는 텍스트 추출 시 이름/학번이 표 하단으로 밀립니다.
  → 단어별 좌표(bbox)로 행·열을 재구성해야 합니다.
- **zip CP949 인코딩.** 압축 해제 시 `utf-8 → cp437→cp949` 폴백이 필요합니다.
- **이미지 회전.** 체류 영수증 스캔은 90도 회전·기울어진 것이 많습니다.

## 4. 규칙 엔진 (⑤)

```python
for rule in rules(expense_type):
    if not rule.enabled: continue
    vals = resolve(rule.requires, doc_set)
    if any(v.confidence < 0.85 for v in vals):
        yield Finding(rule, REVIEW, "판독 불가")   # 신뢰도 강등
        continue
    ok, computed = evaluate(rule, vals)            # 샌드박스 평가
    if not ok:
        yield Finding(rule, rule.severity,
                      message=rule.message.format(**vals, computed=computed),
                      fix=rule.fix.format(**vals, computed=computed),
                      anchors=[v.source for v in vals])  # 원본 페이지·좌표
```

- `expr` 은 **제한된 표현식만** 평가합니다 (`eval` 금지 — `simpleeval` 등 사용).
- `computed` 를 항상 계산해 두어야 `fix` 에서 "**412km 를 기재하세요**" 처럼 정답을 제시할 수 있습니다.
- `anchors` 는 결과 클릭 시 원본 PDF의 해당 페이지·영역으로 이동시키는 데 씁니다.

## 5. 기술 스택 권장안

| 층 | 권장 | 이유 |
|---|---|---|
| 런타임 | **Python 3.11+** | PDF/OCR/Vision 생태계가 전부 여기 있음 |
| GUI | **PySide6 (Qt)** | 단일 언어로 끝남. PDF 뷰어 위젯 내장, 데스크톱 배포 검증됨 |
| PDF | `pypdf`, `pdfplumber`, `pypdfium2`(렌더) | 손상 PDF 폴백 포함 |
| OCR | `PaddleOCR` 또는 `Tesseract(kor)` | 한글 인쇄물 |
| Vision | 로컬 우선, 필요 시 Claude API | **손글씨·통장·신분증 판독** |
| 규칙 | `PyYAML` + `simpleeval` | 담당자가 직접 수정 가능 |
| 배포 | `PyInstaller` (Windows 단일 exe) | |

**대안:** Electron/Tauri + React UI + Python 사이드카.
UI 완성도는 높지만 2개 언어·2개 프로세스를 관리해야 합니다.
사용자가 사업단 담당자 소수라면 **PySide6 단일 스택을 권장**합니다.

## 6. 개인정보 처리 — 타협 불가 조건

이 서류들에는 **주민등록번호 13자리 전체, 계좌번호, 신분증 사본**이 평문으로 들어 있습니다.

1. **전 과정 로컬 처리를 기본값으로.** 추출·판정 모두 오프라인에서 동작해야 합니다.
2. **외부 Vision API 사용은 옵트인.** 켤 때 무엇이 전송되는지 명시하고, 전송 전
   주민번호 뒷자리·계좌번호를 마스킹합니다. (마스킹 후에도 판정 가능한 규칙에만 사용)
3. **중간 산출물(렌더 이미지·추출 JSON)은 검토 종료 시 삭제.**
4. **결과 리포트에 주민번호를 싣지 않습니다.** `홍**(202xxxxx)` 형태로 출력.
5. 로그에 원문 값을 남기지 않습니다.

> 검토 대상이 개인정보 동의서인 앱이 정작 개인정보를 흘리면 안 됩니다.
> 이 항목은 기능이 아니라 **전제 조건**으로 다뤄야 합니다.

## 7. 단계별 구현 순서

| 단계 | 범위 | 확보되는 가치 |
|---|---|---|
| **1** | 지출종류 선택 → 파일 분류 → **L0 서류 완비성**만 검사 | 누락 서류 즉시 통보. 이것만으로도 반려 사유의 상당수가 걸러짐 |
| **2** | 텍스트 추출 + **L1 내부 계산** (시간 합계, 거리 합계, 금액 계산) | 샘플에서 확인된 오류 대부분(총 이동경로 공란 등)이 여기서 잡힘 |
| **3** | **L2 교차 대사** (성명·계좌·시간·금액·기간) | 서류 간 불일치 |
| **4** | OCR/Vision — 손글씨 근무일지, 체류 영수증, 통장·신분증 | 나머지 |
| **5** | **L3 한도** (지침 수치 입력 후) + 묶음 모드(동승 중복 검출) | 규정 준수 |
| **6** | 수정 요청서 내보내기, 규칙 편집 UI | 운영 편의 |

1~3단계는 **OCR 없이도 동작**하고, 샘플에서 실제로 발견된 문제의 대부분을 잡아냅니다.
여기까지 먼저 만들고 쓰기 시작하는 것을 권합니다.
