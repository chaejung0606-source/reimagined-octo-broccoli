# 02. 검토 기준 설계

## 0. 설계의 핵심 아이디어

서류를 통째로 "잘 됐나?" 보는 방식은 규칙이 늘어날수록 무너집니다. 대신 **두 단계로 쪼갭니다.**

```
[1단계] 서류 → 정규화된 필드(Field)로 추출
        "김예린", 240000, 2026-05-31, "59220101565992", 16.0 ...

[2단계] 필드 위에서 규칙(Rule)을 평가
        R-CMN-004: 모든 문서의 계좌번호(정규화) 가 동일한가?
```

이렇게 하면 **지출종류가 늘어나도 추출기는 재사용**되고, 규칙은 YAML 한 줄로 추가됩니다.
그리고 검토 기준을 아래 **4개 층위(Layer)** 로 나눕니다. 이 층위 구분이 이 설계의 뼈대입니다.

| Layer | 이름 | 질문 | 예 |
|---|---|---|---|
| **L0** | 서류 완비성 | 낼 게 다 왔나? | 재학증명서 누락 |
| **L1** | 문서 내부 정합성 | 그 서류 하나만 봐도 틀렸나? | 09:00~14:00인데 6시간이라 적음 |
| **L2** | 문서 간 교차 정합성 | 서류끼리 말이 맞나? | 근무상황부 15h vs 지급내역 20h |
| **L3** | 규정·한도·형식 | 지침을 넘었나? | 월 60시간 초과, 발급 1개월 경과 |

## 1. 판정 등급 (3-상태 + 신뢰도)

손글씨·스캔이 섞여 있어 **"위반"과 "정상"의 2분법은 위험**합니다. 잘못 읽고 반려시키면 앱을 못 씁니다.

| 등급 | 표시 | 의미 | 처리 |
|---|---|---|---|
| `ERROR` | 🔴 수정 필요 | 규정 위반 또는 명백한 불일치 | 반드시 수정 후 재제출 |
| `WARN` | 🟡 확인 요망 | 위반 가능성 있음 / 관행상 확인 필요 | 담당자 판단 |
| `REVIEW` | 🔵 판독 불가 | **추출 신뢰도 미달로 판정 보류** | 사람이 직접 대조 |
| `PASS` | 🟢 이상 없음 | | |

**규칙:** 필드 추출 신뢰도(confidence)가 임계값(기본 0.85) 미만이면, 그 필드를 쓰는 규칙은
결과와 무관하게 `REVIEW`로 강등합니다. 손글씨 근무일지가 대표적입니다.

각 결과는 반드시 아래 4가지를 함께 제시합니다.

```
[R-TRV-006] 🔴 총 이동경로 합계가 비어 있습니다
  근거   출장증빙 p.1 · '이동경로' 블록
  검출값  출발지→도착지 206km, 도착지→출발지 206km, 총 이동경로 (공란)
  조치    총 이동경로 칸에 412km 를 기재하세요.
```

→ **"수정해야 될 부분을 정리해서 알려준다"** 는 요구사항은 `조치` 문구를 규칙마다
템플릿으로 들고 있게 해서 충족합니다.

> 하위 유형: **TA형(나형)** / **서포터즈형(가형)** — 앱에서 먼저 선택하게 합니다.

| 유형 | 필수 서류 |
|---|---|
| TA형 | 양식1 추천·서약서 / 양식2 개인정보 동의서 / 양식3 신분증·통장 / 양식4 재학증명서 / 양식5 근무상황부 |

## 7. 규칙 표현 방식

규칙은 코드가 아니라 **YAML 데이터**로 둡니다. 담당자가 직접 고칠 수 있어야 지침 개정을 따라갈 수 있습니다.

```yaml
- id: R-TRV-006
  layer: L1
  title: 총 이동경로 합계 불일치
  severity: ERROR
  applies_to: [출장비]
  requires: [travel.dist_out, travel.dist_back, travel.dist_total]
  expr: "travel.dist_total == travel.dist_out + travel.dist_back"
  message: "총 이동경로({travel.dist_total}km)가 편도 합계({travel.dist_out}+{travel.dist_back})와 다릅니다."
  fix: "총 이동경로 칸에 {travel.dist_out + travel.dist_back}km 를 기재하세요."
```

- `requires` 의 필드가 **하나라도 추출 실패/저신뢰면** 자동으로 `REVIEW` 강등
- `expr` 은 샌드박스 평가 (임의 코드 실행 금지)
- `fix` 는 계산된 정답까지 제시 → 사용자는 그대로 고치면 됨

실제 초안은 [`rules/`](../rules) 아래 4개 파일에 담았습니다.

## 8. 확정이 필요한 사항

설계는 샘플만으로 여기까지 세웠습니다. 아래는 **규정 문서가 있어야 채울 수 있는 값**입니다.

1. **근로장학금 지침** — 1일/월 근로시간 한도, 유형별 기준단가((가)형 12,000 / (나)형 15,000·20,000 확정 여부), 주말·공휴일 근로 허용 여부
2. **혁신인재지원금 지침** — 소학회 진행요원비 정액 240,000원의 산정 근거(정액인지 시간급인지), 소학회 최소 인원, 월 지급 상한
3. **강원대 여비 규정** — 일비·식비·숙박비 한도, 자가용 km당 단가, 공용차량 이용 시 정산 범위
4. **동승 중복청구 판정 기준** — 같은 신청서 다인 출장의 통행료 처리 원칙
5. **재학증명서 유효기간** — 샘플 서식엔 "최근 1개월", 지침과 일치하는지
6. 서류가 **반려되는 기준선** — ERROR 1건이면 반려인지, 담당자 재량인지

이 값들이 정해지기 전에도 L0~L2 규칙(전체의 약 80%)은 그대로 작동합니다.
L3 한도 규칙만 설정값으로 비워두고 시작하면 됩니다.
