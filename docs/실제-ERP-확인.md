# 실제 ERP 에서 담당자가 확인할 것

Claude 는 실제 ERP 를 돌릴 수 없습니다(로그인은 사람). 그래서 모의 화면으로 통과한 것도 **실제 ERP 에서 한 번은 담당자가** 확인해야 합니다.
이 문서는 그 확인을 **무엇을 · 어떤 순서로 · 무엇을 보면 되는지** 적은 것입니다. 확인이 끝나면 맨 아래 '알려 주실 것' 만 보내 주세요.

## 0. 시작 전에 (매번)

1. **업데이트 받기** — 앱 위쪽에 '새 업데이트' 띠가 보이면 [적용] → [새로고침]. 띠가 없으면 톱니(설정) 옆 사용자 메뉴 → 업데이트 → [확인].
   '최신입니다' 가 보이면 됩니다.
2. **기록 파일 위치** — `C:\Users\<사용자 이름>\.claim-downloader\_실행로그.txt`
   (탐색기 주소창에 `%USERPROFILE%\.claim-downloader` 를 넣으면 열립니다). 앱의 각 화면 [진행 기록] 탭에도 같은 글이 보입니다.
   **보낼 때는 오른쪽 위 사용자 메뉴 → [문제 보내기]** — 이름 · 학번 · 계좌 · 주민번호를 가린 최근 기록이 복사됩니다. 그대로 채팅에 붙여 넣으면 됩니다.
3. **원칙 세 가지**
   - 처음에는 늘 **[미리 보기]** → 표를 보고 → 체크를 풀고 **[ERP 에 넣기]**. 미리 보기는 ERP 를 건드리지 않습니다.
   - 시험은 **학생(또는 건) 1명만** 체크해서. 끝까지 되면 나머지를 넣습니다.
   - 앱은 ERP **[저장](임시저장)** 까지만 누릅니다. **[신청] 은 담당자가 화면을 보고 직접** 누릅니다. 시험으로 만든 임시저장 건은 담당자가 지웁니다.

## 1. 장학금 — (가) 서포터즈 8월 다시 넣기 (가장 먼저)

**왜**: 2026-10-14 19:47 시험에서 1번 학생이 멈췄습니다. 로그에는 소득자를 고른 뒤 ERP 계좌 칸이 **비어 있었다**고 남았고, 앱이 [예금주조회] 를 누르자
ERP 가 `예금주조회시 은행/계좌번호는 필수입력입니다.` 라고 했습니다. 담당자 말씀으로는 계좌가 정상이었으니, ① 그 학생이 ERP 인적정보에 계좌가 없었는지
② ERP 가 계좌를 늦게 채웠는지 둘 중 하나입니다. 지금 판은 ~3초 기다린 뒤에도 비어 있으면 **명단 엑셀의 은행 · 계좌를 넣고** [예금주조회] 를 누릅니다.

**순서**

1. ERP: 결의서내역 → **[일반청구]** 로 새 청구서(작성 화면)를 띄웁니다.
2. 앱: 홈 → **일반청구** → 그 달 폴더(`(가) 서포터즈\8월` 처럼 명단 엑셀 + '공통' · '개별' 폴더가 든 폴더)를 끌어다 놓습니다. 청구 종류가 **장학금** 인지 봅니다.
3. 오른쪽 학생 표에서 **1번 학생만** 체크 → [미리 보기] → 표의 이름 · 학번 · 청구액 · 첨부 수가 맞는지 → 미리 보기 체크 해제 → [ERP 에 넣기] → 확인 창에서 [ERP 에 넣기].

**[진행 기록] 에서 볼 줄** (순서대로)

| 줄 | 뜻 |
|---|---|
| `── 1. 이름 (학번 … · …원)` | 이 학생 시작 |
| `소득자 검색(인적정보, 학번): '…' → 1행` → `소득자 자동 선택: 이름(학번) — …` | 학번으로 찾아 골랐다 |
| `소득구분이 '기타소득' 로 바뀌어 있어 다시 '장학금' 로 고릅니다 (소득자를 고른 뒤)` | **정상** — ERP 가 소득자를 고를 때마다 되돌려서 앱이 다시 고침 |
| **`소득자를 고른 뒤 ERP 계좌: 은행 … · 계좌 … · 예금주 … · 예금주조회 …`** | **이 줄이 이번 확인의 핵심입니다.** 계좌가 `(비어 있음)` 이면 ①(ERP 에 계좌 없음)이었던 것 |
| `ERP 계좌 없음: 명단 … / ERP … — 개별증빙 PDF N개에서 …` → `계좌를 … 의 … 로 넣음 (…)` | 계좌가 비어 명단 값을 넣었다 |
| `[예금주조회] 누름 (… · 은행 … · 계좌 …)` → `예금주조회 결과: 성공:이름` | 앱이 조회해 '성공' |
| `첨부 N개 올림 (첨부문서 0 → N)` | 공통 + 개별 파일이 다 올라감 |
| `임시저장 결과: 임시저장 됨` → `장학금 청구 끝 — 임시저장 1명` | 끝 |
| `신청 전 대조: 청구내역 1줄 — 확인할 것 1건` · `! 명단에 있는데 청구내역에 없는 사람 N명` | **1명만 넣었으니 정상.** 다 넣은 뒤에는 '명단과 맞습니다' 가 나와야 합니다 |

**ERP 화면에서 볼 것**: 청구내역 표에 그 학생 한 줄 · 소득구분 **장학금** · 합계 줄 **공제합계 0** · 그 줄의 첨부 수 · 적요 `02_2026년도 8월 (가)형 근로장학금_이름`.

**이상 신호와 할 일**

- 노란 띠 `… 명단의 … 를 넣지 못했습니다(…)` — 은행 이름이 ERP 보기와 안 맞은 것입니다. ERP 에서 은행을 고르고 계좌를 넣은 뒤 [예금주조회] 로 '성공' → [계속].
  띠 글에 `보기가 여럿(농협은행 · …)` 이 보이면 명단에 '농협' 처럼 짧게 적힌 것 — 명단 엑셀의 은행을 '농협은행' 또는 지역 농협이면 그 이름으로 고쳐 두면 다음부터 앱이 고릅니다.
- 노란 띠 `예금주조회 결과가 …` — ERP 에서 [예금주조회] 를 눌러 '성공:이름' 이 나오면 [계속].
- 1명이 끝까지 되면 → 나머지 학생을 체크하고 같은 방법으로(앞서 저장된 학생은 체크가 풀려 있습니다). 같은 청구서에 이어 붙습니다.
- 다 넣은 뒤 결과 창 위쪽 **'신청 전 대조'** 가 '명단과 맞습니다' 인지 봅니다. 아니면 '신청 전 확인할 것' 에 두 번 들어간 사람 · 빠진 사람 · 다른 금액 ·
  명단에 없는 줄이 적혀 있습니다. ERP 에서 고친 뒤 오른쪽 아래 **[청구내역 대조]** 를 다시 누르면 다시 봅니다(읽기만 합니다).
- 앱을 껐다 켜서 같은 폴더를 다시 넣으려 하면 '이미 넣은 적이 있습니다' 창이 이력(언제 · 결의번호 · 몇 명)과 **이미 저장한 학생 이름**을 보여 줍니다.
  ERP 청구내역에 그 학생이 있으면 체크를 풀고 넣으세요.

## 2. 청구서 받기 — 일반청구로 브라우저를 먼저 연 뒤

**왜**: 전에는 일반청구 화면이 브라우저를 먼저 열면 받기 화면이 보관 폴더를 훑지 않은 채 목록을 읽어 **이미 받은 청구서를 다시 받을 수 있었습니다**(2026-10-14 점검에서 고침).

1. 앱을 새로 켜고 **일반청구** 화면에서 브라우저를 엽니다(장학금 넣기를 했다면 그 브라우저 그대로).
2. ERP 에서 **'청구서(일반)' 탭을 닫고** 결의서내역 목록을 띄웁니다. (탭이 열린 채 받기를 시작하면 주황 띠로 '일반청구 작성 화면이 열려 있습니다' 가 뜹니다 — 탭을 닫고 목록을 띄운 뒤 [목록을 띄웠어요 · 계속].)
3. **청구서 받기** 화면 → [목록 읽기].

(받기 화면에서 [브라우저 열기] 로 시작했다면 목록을 띄우는 순간 앱이 **저절로** [목록 읽기] 를 합니다 — 상태가 '목록 발견' 으로 바뀌고 읽습니다.
안 되면 직접 누르면 됩니다. 싫으면 설정 → 동작에서 끕니다.)

**정상**: 아래 상태 글에 **`보관 폴더를 읽는 중…`** 이 잠깐 보인 뒤 목록을 읽고, '새로 받을 건' 수가 평소(받기 화면에서 브라우저를 열었을 때)와 같습니다.
이미 받아 둔 청구서는 '받음' 으로 빠집니다. 받을 건이 있으면 [앞 1건만 시험] 으로 하나 받아 비목 폴더 **바로 아래**에 생기는지 봅니다.

**이상**: 이미 `업로드\` 에 있는 청구서가 '새로 받을 건' 에 보이면 **받지 말고** 멈춘 뒤 `_실행로그.txt` 를 보내 주세요.

## 3. 결의번호 324 정리 (시험 때 섞인 것)

2026-10-14 저녁 같은 소학회 진행요원비 폴더를 두 번 넣어 결의번호 **324** 한 청구서에 줄이 섞였습니다.

- 19:22 — 그때는 '혁신인재지원금' 종류가 없던 판이라 **장학금**(비목 장학금 · 적요 `02_…`)으로 6줄
- 19:30 — **혁신인재지원금**(비목 교육·연구프로그램개발·운영비 · 적요 `03_…`)으로 6줄

앱은 아무것도 지우지 않으므로 ERP 에서 담당자가 정리합니다. **권하는 방법: 324 를 통째로 지우고 새로 넣기** — 대표적요(`#APPL_CONT`)가 첫 저장 때의
`02_…` 로 남아 있을 수 있어서입니다.

1. ERP 결의서내역에서 324(진행구분 임시저장)를 골라 [삭제].
2. 결의서내역 → [일반청구] 로 새 청구서.
3. 앱 일반청구 → 그 폴더 → 청구 종류 **혁신인재지원금**(폴더 이름에 '진행요원' 이 있으면 '자동' 이 알아서 고릅니다) → [미리 보기] → [ERP 에 넣기].
   대표적요가 `03_` 로 시작하는지 미리 보기 표 위에서 봅니다. 넣기 전에 '이미 넣은 적이 있습니다'(전에는 '장학금' 으로 넣었는데 …) 창이 뜨면
   324 를 지운 것이 맞으니 [예].
4. 끝나면 결과 창의 '신청 전 대조' 가 '명단과 맞습니다' 인지 봅니다.

지우지 않고 고치려면: 324 를 열어 청구내역 표에서 **비목이 장학금인 6줄**을 담당자가 [삭제] 하고, 위쪽 대표적요가 `03_…` 인지 고칩니다.
그다음 앱에서 그 폴더(혁신인재지원금)를 고르고 **[청구내역 대조]** — '명단에 없는 줄' 이 사라지고 '명단과 맞습니다' 가 나오면 끝입니다.
지난 시험으로 만든 다른 임시저장 건(322 등)도 같이 지워 주세요.

## 4. 작업 표시줄 아이콘 (고정하면 옛 그림이 뜨던 것)

1. 앱 → 톱니(설정) → **[바로가기 다시 만들기]** → 결과 글이 '만들었습니다' 인지 봅니다.
2. 작업 표시줄의 COSS 업무데스크 아이콘 오른쪽 클릭 → **작업 표시줄에서 제거**.
3. 바탕화면의 COSS 업무데스크 바로가기 오른쪽 클릭 → (윈도우 11 은 '추가 옵션 표시') → **작업 표시줄에 고정**.

**정상**: 고정한 아이콘이 새 그림(흰 둥근 판 + 라벤더 C)이고, 앱을 켜면 **단추가 하나**(고정한 자리에서 켜짐).
**이상**: 그래도 옛 그림이면 윈도우가 그림을 기억해 둔 것입니다. 로그아웃 후 다시 로그인하면 대개 바뀝니다. 그래도 같으면 설정 단추를 눌렀을 때의 결과 글과
`_실행로그.txt` 의 '바로가기' 줄을 보내 주세요. (단추가 둘로 뜨는 것은 2026-10-13 부터 남은 문제로, 쓰는 데 지장은 없습니다.)

## 5. 일반청구 — 세금계산서 물품 · 용역 1건 (여유 있을 때)

아직 실제 ERP 에서 한 번도 끝까지 해 보지 않은 흐름입니다. 급하지 않습니다.

1. 설정 → 일반청구 → **계산서수신메일**에 담당자 메일을 넣습니다(산학협력단 전체 계산서 중 내 것만 보이게).
2. 지출 폴더 하나(견적서 · 거래명세서 · 세금계산서 PDF 등)를 일반청구에 넣고 [내용 읽기] → 오른쪽 칸 값 확인 → [미리 보기] → [ERP 에 넣기].
3. 앱이 세금계산서 [선택] 팝업에서 [조회] 까지 하고, 맞는 계산서가 하나뿐이면 고릅니다. 이어서 입금처 돋보기에서 상호로 검색해 하나뿐이면 고릅니다.
4. 사람이 첨부 · 예금주조회를 한 뒤 앱의 **[임시저장]**.

**볼 것**: [진행 기록] 의 `세금계산서 …` · `입금처 …` 줄. 자동으로 못 고르면 팝업이 열린 채 '목록에서 고르고 [확인]' 이라고 나옵니다 — 그대로 고르면 됩니다.
그 상태(검색 뒤)에서 [진행 기록] 구석의 **[화면 구조 저장]** 을 눌러 `_화면구조.txt` 를 보내 주시면 입금처 자동 선택을 실제 목록 모양에 맞출 수 있습니다.

## 6. 새로 들어온 것 한 번씩 (2026-10-15)

- **문제 보내기**: 사용자 메뉴 → [문제 보내기] → 붙여 넣은 글에 학생 이름 · 계좌번호가 보이지 않는지 한 번 훑어봅니다. 보이면 그 줄을 알려 주세요(가리는 규칙을 고칩니다).
- **처음 쓰시나요?**: 동료 PC 에 새로 깔았을 때만 홈에 뜹니다(담당자 PC 에는 안 뜸). 사용자 메뉴 '처음 안내 다시 보기' 로 볼 수 있습니다.
- **은행 이름**: 명단에 '농협' · '수협' 처럼 짧게 적힌 학생의 계좌를 앱이 넣어야 할 때, ERP 보기에 농협은행과 지역 농협이 둘 다 있으면 고르지 않고 노란 띠로 묻습니다.

## 7. 새 청구서 자동 열기 · 로그인 뒤 메뉴 이동 — 화면 구조 받기 (2026-10-19)

담당자가 허락한 두 가지(앱이 [새 청구서] · [일반청구] 를 누름 / 로그인 뒤 결의서내역까지 앱이 메뉴를 누름)를 만들기 전에 화면을 실측합니다.
아래 순서대로 **[화면 구조 저장]**(받기 화면 · 일반청구 화면의 [진행 기록] 구석)을 누르면 저장할 때마다 `_화면구조_모음.txt` 에 차례로 쌓입니다.
앱은 이 동안 아무것도 누르지 않습니다. 화면을 옮기는 것은 모두 사람이 합니다.

1. 앱에서 브라우저를 열고 **로그인만** 합니다. 메뉴를 누르기 전 첫 화면에서 저장 — ①
2. **과제관리** 메뉴를 눌러(또는 마우스를 올려) 아래 **과제정보** 가 보이는 상태에서 저장 — ②
   마우스를 브라우저 밖으로 옮기면 메뉴가 닫혀 저장할 수 없으면 건너뛰고 "마우스를 올려야 열리는 메뉴" 라고 알려 주세요.
3. **과제정보** 를 누른 화면(청구서 탭을 누르기 전)에서 저장 — ③. 과제가 여러 개라 목록에서 고르는 화면이면 그 상태에서 저장하고, 어느 과제를 고르는지(과제명) 알려 주세요.
4. **청구서** 탭 → 결의서내역이 뜬 화면에서 저장 — ④
5. 결의서내역의 **[일반청구]** 를 눌러 '청구서(일반)' 탭이 뜬 **빈 작성 화면**에서 저장 — ⑤
6. 그 탭을 둔 채 결의서내역으로 돌아가 **[일반청구]** 를 한 번 더 누릅니다. 탭이 하나 더 생겼는지, 있던 탭이 비워졌는지 글로 알려 주시고 저장 — ⑥
7. **지워도 되는 시험용 임시저장 건**을 연 작성 화면에서 **[새 청구서]** 를 누릅니다. 확인 창이 뜨면 그 글자 그대로, 화면이 비워졌는지,
   탭이 새로 생겼는지 알려 주시고 저장 — ⑦. ([새 청구서] 가 저장된 건에 무엇을 하는지 아직 모르니 실제 청구 건에서는 하지 마세요.)
8. `C:\Users\<사용자>\.claim-downloader\_화면구조_모음.txt` 파일 하나를 보내 주세요. 작성 화면은 빈 상태에서 저장했는지 한 번 확인합니다.

## 알려 주실 것

- 1번: **`소득자를 고른 뒤 ERP 계좌:` 줄**(계좌 숫자는 가리고 '비어 있음' 인지만), 끝까지 저장됐는지, 멈췄다면 노란 띠 글.
- 2번: '보관 폴더를 읽는 중' 이 보였는지, 새로 받을 건 수가 평소와 같은지.
- 3번: 정리했는지(답만).
- 4번: 고정 아이콘 그림이 바뀌었는지, 단추가 하나인지.
- 7번: `_화면구조_모음.txt` 와 6 · 7 단계에서 본 것(탭 · 확인 창 글자).
- 그 밖에 이상한 것은 사용자 메뉴 → **[문제 보내기]** 로 복사한 기록(개인정보는 앱이 가립니다 — 그래도 한 번 훑어보고).
