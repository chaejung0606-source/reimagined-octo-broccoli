# QA·검증 플레이북 — COSS 업무데스크 (reimagined-octo-broccoli)

이 앱은 웹 서비스가 아니라 **PySide6 데스크톱 앱 + Playwright 로 ERP 화면을 조작**하는 업무 자동화 도구다.
그래서 "브라우저 클릭 테스트"가 아니라 **모의 ERP 화면 + 실제 ERP(담당자 확인)** 이라는 형태로 QA 가 돈다.
innovation-fund 의 [QA 플레이북](https://github.com/chaejung0606-source/-)(웹용)의 원칙을 이 앱 구조에 맞게 옮긴 것이다.

> 돈이 나가는 입력(청구서 작성)을 자동화하는 앱이라, **QA 의 핵심은 '값이 맞는가'보다 '앱이 눌러도 되는 것만 누르는가 · 사람 손을 어디서 넘겨받는가'** 다.
> CLAUDE.md 가 이 앱의 단일 근거 문서다 — 아래는 그 §4·§7·§9·§11 을 QA 관점으로 묶은 것이고, 충돌하면 CLAUDE.md 가 이긴다.

---

## 0. 핵심 원칙

1. **Claude 는 실제 ERP 를 직접 돌리지 않는다.** 로그인은 사람이 한다(§9). 자동 검증은 **모의 ERP 화면**(가상 스크롤 그리드·상세 프레임·OZ 저장 대화상자·회의록등록 창·파일등록 창)으로, 실제 확인은 **담당자가 [시험]·'앞 1건만'** 으로 한다.
2. **두 층으로 본다.**
   - **결정적(pytest)** — 단위 테스트 + 실제 Chromium 으로 모의 ERP 에 끝까지 넣어 보는 흐름 테스트. 통과/실패가 딱 떨어진다. CI 가 푸시마다 막는다.
   - **화면 확인(사람)** — UI 를 건드렸으면 실제로 앱을 띄워 본다(`python -m claim_downloader.ui.app`). 리눅스 컨테이너엔 ERP 가 없으니 모의 페이지로 흐름을 돌려 보고, **진짜 ERP 는 담당자가** 확인한다.
3. **추측으로 ERP 화면을 바꾸지 않는다(§4).** 새 화면을 자동화하기 전에 **진단 모드([화면 구조 저장])로 실측** → CLAUDE.md 에 그 화면 절(프레임·필드·**절대 누르지 않을 버튼 id**)을 적은 뒤에 구현한다. "(추정)" 은 담당자 확인 전까지 코드로 넣지 않는다.
4. **고치기 전에 재현부터.** 담당자가 겪은 문제는 `~/.claim-downloader/_실행로그.txt`(→ [문제 보내기]로 가린 `_공유용로그.txt`)로 원인을 보고, 그 상황을 pytest 로 고정한 뒤 고친다.
5. **배포 = 담당자 PC 에서 바로 도는 코드(§3).** 배포 브랜치 `claude/expense-document-review-criteria-yzji9p` 에 올린 커밋은 updater 가 `git pull` 로 내려 곧바로 실행된다. 그래서 **점검 보고서·이 문서 같은 문서는 `checks/daily` 브랜치**에 둔다(배포 브랜치에 올리면 담당자 앱에 '새 업데이트'가 뜬다).

## 1. 결정적 테스트 — `python -m pytest -q`

CI(`.github/workflows/ci.yml`)가 푸시마다 도는 네 검사가 1차 그물이다. 로컬에서도 같은 걸 돌린다.

| 검사 | 명령 | 무엇을 막나 |
|---|---|---|
| 테스트 | `python -m pytest -q` | 단위 + 모의 ERP 흐름. 아래 1-1·1-2 |
| 문법 | `python -m compileall -q src tools` | import 안 되는 깨진 파일 |
| 이름 오류 | `ruff check --select F821,F822,F823,F811,F632,F701,F702,F704,F706,F707,E9 src tools tests` | 없는 이름·겹친 정의 — **단추를 눌러야 터지던 NameError 가 배포된 적 있다**(화면 코드는 CI 에서 안 돌아서) |
| 개인정보 혼입 | `git ls-files '*.pdf' '*.xlsx' …` | 계좌·실명 든 파일이 저장소에 올라갔는지(.gitignore 를 믿지 않는다) |

의존성 취약점은 `pip-audit`(또는 `pip-audit -r`)로 따로 본다 — 결과는 `checks/daily` 보고서에.

### 1-1. 단위 테스트 — 로직을 함수째로 (브라우저·PySide6 없이)
파일명 조합·비목 판정·대상 고르기·보관 스캔·명단 엑셀 읽기·금액/지역 판정 같은 **입력→출력이 정해진 로직**은 가짜 데이터로 직접 검사한다.
가짜 데이터는 코드로 만든다(`tests/conftest.py` 의 `make_row()`, `tests/test_minutes.py` 의 `sample()`) — **실제 PDF·엑셀을 쓰지 않는다**(§10). 커버 중인 것: `test_naming`·`test_targets`·`test_archive`·`test_scholarship`·`test_card`·`test_personal`·`test_select_match`·`test_reconcile`·`test_minutes`·`test_windows_files` 등.

### 1-2. 모의 ERP 흐름 테스트 — 실제 Chromium 으로 끝까지 (이 앱의 '클릭 테스트')
`test_scholarship`·`test_card_erp`·`test_claims`·`test_personal`·`test_logout`·`test_diagnose` 는 `playwright.sync_api` 를 `importorskip` 으로 불러(없으면 건너뜀) **실제 Chromium**(`/opt/pw-browsers/chromium`)으로 **실측 id 그대로 만든 모의 ERP 화면**에 값을 넣고 [저장]까지 눌러 본다. 모의 화면이 실측의 함정을 그대로 재현해야 의미가 있다:
- **두 탭이 같은 id**(일반청구/인건비) — 보이는 요소를 고르는지
- **저장 뒤 프레임 다시 열림** — 저장 성공 판정(`#REQ_CNT` 생김 / `#APPR_DIV_CD`=40)
- **가상 스크롤 결과 그리드**(보이는 곳만 그림) — 문서번호/학번으로 스크롤하며 찾는지
- **소득자 팝업 같은 이름 두 행** — 학번으로 고르는지 · **회의록등록/파일등록 창** · **확인 대화상자**(confirm) 처리
모의로 통과해도 **실제 ERP 확인은 담당자가 [시험]·'앞 1건만'** 으로(`docs/실제-ERP-확인.md`).

## 2. 화면 확인 (사람) — UI 를 건드렸을 때

- `python -m claim_downloader.ui.app` 로 띄워 **실제로 눌러 본다**(CLAUDE.md §4). 홈 타일·독·작업 탭·오른쪽 패널·노란 띠·결과 표 창이 깨지지 않는지, 낮은 창(1024×640·페이지<720)에서 접히는지(§17).
- 디자인 규칙은 `tests/test_design.py` 가 일부 지킨다(글꼴 4종·토큰 대비 WCAG AA). 색/모서리/그림자는 `ui/tokens.py` 로만.
- ERP 화면 흐름은 모의 페이지로 돌려 보고, **진짜 ERP·한글(.hwpx) 열기는 담당자 확인**(격자 검사를 통과해도 한글이 거부한 적 있다 §13).

## 3. 논리적 오류 — 이 앱에서 데인 자리 (CLAUDE.md §7·§8)

- **보관 스캔이 조용히 실패하면 전부 중복 다운로드된다(§7.4).** 저장 폴더 미지정/없음이면 ⚠⚠ 경고 + 받기 전에 다시 묻는다. 이 안전장치를 없애지 않는다.
- **중복 판단은 문서번호로만(§7.6).** 금액+내용으로 묶으면 서로 다른 건을 같다고 오판해 숨는다(4월 기관부담금이 금액 같은 5월 건과 오매칭된 적 있다).
- **가상 스크롤(§7.2).** 전체 수집 뒤 스크롤이 맨 아래면 윗 행 DOM 이 없다 → 행은 `r` 로 바로 찾지 말고 **문서번호로 스크롤하며** 찾는다(`erp.select_row`). 결과 그리드 읽기도 보이는 줄만 세지 않도록.
- **첫 evaluate 타이밍(§7.1).** 목록이 보여도 첫 `frame.evaluate()` 가 False/예외일 수 있다 → 재시도 루프(`wait_for_grid`, 0.5초×40).
- **숨은 탭의 그리드는 일부만 읽힌다(§7.11).** 다른 탭 뒤에 숨은 목록은 높이 0 이라 가상 스크롤이 안 움직여 처음 그린 줄만 읽힌다 → 보이는지 보고(`grid_shown`) 아니면 앞으로 가져오거나 멈춘다.
- **파일명(§8).** 금지문자 `\ / : * ? " < > |` 는 공백 치환, 경로 240자 넘으면 적요 가운데 줄임(`fit_name`), 동명은 덮어쓰지 않고 `_2`. 비목 판정 순서(적요 `0N_` → `[…]` → 상세 표 → 금액 줄, 못 정하면 `00. 미분류`; `0N.` 점 형식도 받는다).
- **저장 성공 판정.** 작성 화면이 다시 열려 `#REQ_CNT` 가 생기거나 `#APPR_DIV_CD`=40 이 되는 것으로 본다(옛 `REQ_SEQ_NO`·`MOD_YN` 가정은 틀렸었다 §14⑤). 빈 줄·'조회된 내역 없습니다' 는 청구내역 줄로 세지 않는다.

## 4. 절차·안전 오류 — 이 앱 QA 의 1순위 (CLAUDE.md §9 · `tests/test_safety.py`)

돈이 나가는 입력을 자동화하므로, 아래는 **기능보다 먼저** 본다. `test_safety.py` 가 코드로 지킨다 — 새 기능 때문에 이 테스트를 고쳐야 하면 §9 원칙부터 다시 읽는다.

- **ERP 아이디/비밀번호를 코드·설정·로그·캐시 어디에도 저장하지 않는다.** 브라우저 프로필·쿠키(`storage_state`·`user_data_dir`)도 안 남긴다. (예외: 주차등록 사이트 로그인만 `_주차로그인.json`, 비밀번호는 윈도우 DPAPI — §20.)
- **돈이 나가는 입력은 "자동 입력 → 요약 → 임시저장까지 → 사람이 [신청]"(§9).** 앱이 누르는 건 ERP [저장](임시저장) 하나뿐, **[신청] 자동 클릭 금지**. 기본값 dry-run(미리 보기). 금액·계좌·건수를 로그에 남긴다.
- **누르는 버튼은 허용 목록으로만.** `test_safety.py` 가 ERP 에서 누르는 대상의 허용 목록·입력(`fill`/`type`) 금지·로그인 정보 저장 금지를 검사한다. 조회/삭제/초기화/새 청구서/일괄예금주조회 등은 누르지 않는다(단, CLAUDE.md 가 허락한 것 — 예금주조회·#P10/#P11·로그아웃 — 만 예외).
- **`set_input_files` 는 `claims/` 안에서만**(파일 첨부 자동화). 받기 코드(erp.py)엔 끝까지 값 넣기가 없다.
- **`업로드/` 폴더 쓰기 금지·기존 파일 덮어쓰기 금지(§2·§9).** `naming.ensure_not_upload()` 가 막는다. 보관 스캔은 `업로드/`까지 읽기만.
- **진단 모드는 읽기만(§4).** 누르거나 값을 넣지 않는다(`test_safety`). 비밀번호·파일 칸 값은 적지 않는다.

## 5. 개인정보 (CLAUDE.md §10)

- 청구서·엑셀엔 계좌·실명이 있다. `.gitignore`(`*.pdf`·`*.xlsx`·기록 파일)를 **풀지 않고**, CI 혼입 검사·`tools/make_bundle.py` 의 `NEVER_PACK` 이 한 번 더 막는다.
- 테스트는 가짜 데이터를 코드로 만든다(실제 파일 금지). 실측 파일(`_화면구조.txt` 등)엔 계좌·사번이 섞일 수 있어 **저장소에 올리지 않고** CLAUDE.md 엔 요소 id·뜻·보기 값만 적는다.
- 담당자 로그 공유는 [문제 보내기](`share_log.py`)로 가린 사본을 쓴다.

## 6. 보고 (checks/daily)

- 매일/수시 점검 결과는 `docs/checks/YYYY-MM-DD.md` + `README.md` 한 줄로 `checks/daily` 브랜치에 커밋(배포 브랜치 아님).
- 담은 것: 최신화·`pytest` 통과 수·`ruff`/`compileall`/개인정보 검사·`pip-audit` 결과, 직전 이후 커밋의 변경분 품질 검토(특히 **누르는 버튼·안전원칙을 건드렸는지**), 미실측 가정이 코드에 들어갔는지.
- **이 레포는 공격·방어(보안 침투) 점검을 하지 않는다**(담당자 결정 — 호스팅되는 플랫폼이 아니라 로컬 데스크톱 도구). 저장형 자격증명(주차 DPAPI)·개인정보 취급만 '지켜볼 항목(C)'으로 본다.
