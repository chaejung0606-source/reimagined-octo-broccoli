# 05. 앱 사용 안내

화면은 네 개입니다. 왼쪽 사이드바로 오갑니다.

---

## 1. 검토

지출종류를 고르고 서류 폴더를 지정한 뒤 **검토 시작**을 누릅니다.

| 입력 | 설명 |
|---|---|
| 지출종류 | 근로장학금 · 혁신인재지원금 · 출장비 |
| 하위 유형 | 근로장학금만 해당 — TA형((나)형) / 서포터즈형((가)형) |
| 서류 폴더 | 제출자 한 명의 서류가 담긴 폴더 |
| 제출자 | 비우면 폴더명을 씁니다 |
| 지급내역 | 사업단이 따로 보관하는 마스터 문서. 폴더 밖에 있을 때만 지정 |
| 일괄 검토 | 하위 폴더 하나를 제출자 한 명으로 보고 한 번에 처리 |

상단 타일은 **검토 대상 / 수정 필요 / 확인 요망 / 판독 불가** 건수입니다.
아래 목록에서 항목을 누르면 오른쪽에 [검출 · 조치 · 근거]가 나옵니다.

**수정 요청서 저장**을 누르면 제출자에게 그대로 보낼 수 있는 마크다운 표가 나옵니다.
주민등록번호·계좌번호는 자동으로 가려집니다.

---

## 2. 파일별 보완사항

**"어떤 파일을 무엇 때문에 고쳐야 하는가"** 를 보는 화면입니다.

규칙 단위로 나열하면 제출자에게 전달할 때 파일별로 다시 묶어야 하므로,
처음부터 파일 카드로 보여 줍니다.

- 카드 하나 = 파일 하나. 색 막대는 그 파일의 지적 구성비입니다.
- 카드를 누르면 그 파일에서 나온 지적만 모여 나옵니다.
- 지적이 심한 파일이 앞에 옵니다.
- `서류 전체` 카드는 **특정 파일에 속하지 않는 지적**(필수 서류 누락 등)입니다.

한 지적이 두 파일을 근거로 하면 양쪽 카드에 모두 걸립니다. 예를 들어
'교통비 금액이 영수증 합계와 불일치'는 출장증빙과 영수증 파일 양쪽에 나타납니다.

## 3. 검토 기준

기준을 확인하고 고칩니다. **검토 단계(L0~L3)별로 묶여** 있습니다.

고칠 수 있는 것:

| 항목 | 설명 |
|---|---|
| 등급 | 수정 필요 / 확인 요망 / 참고 |
| 사용 여부 | 끄면 그 기준으로 검사하지 않습니다 |
| 검출 문구 | 결과에 나오는 설명 |
| 조치 문구 | 제출자에게 전달할 안내 |
| 한도·기준값 | 근로시간 한도, 단가, 여비 한도 등 |

> 문구 안의 `{중괄호}` 는 검토할 때 실제 값으로 바뀝니다. 그대로 두세요.

목록에 붙는 표시:

- `미구현` — 아직 자동 판정하지 않는 기준입니다. 조용히 통과시키지 않고 결과에 남깁니다.
- `사용 안 함` — 꺼 둔 기준
- `수정됨` — 기본값에서 고친 기준

**한도값을 넣으면 그 기준이 자동으로 켜집니다.** 예를 들어 `자가용 km당 단가`에
값을 넣으면 여비 산정 검사(R-TRV-027)가 활성화됩니다. 비워 두면 '규정값 미설정'
으로 검사하지 않습니다.

### 고친 내용은 어디에 저장되나

```
rules/*.yaml          ← 배포본. 업데이트가 덮어씁니다
~/.expense-review/    ← 앱에서 고친 내용. 업데이트해도 유지됩니다
  rule-overrides.yaml
  settings.json
```

**배포본 파일은 앱이 절대 건드리지 않습니다.** 이렇게 나누지 않으면 담당자가
등급이나 한도를 고쳐 둔 상태에서 업데이트가 올 때 충돌이 나거나 수정 내용이
조용히 날아갑니다.

되돌리려면 **기본값으로** 를 누르거나 `rule-overrides.yaml` 에서 해당 항목을 지웁니다.

## 4. 설정

### 화면 모양

세 가지 테마가 있습니다. 누르면 바로 바뀌고, 다음에 열 때도 유지됩니다.

| 테마 | 설명 |
|---|---|
| **퍼플 갤럭시** (기본) | 딥 퍼플 별하늘 바탕에 라벤더 카드. 부드러운 입체감 |
| **포근한 체크** | 크림색 깅엄 바탕, 딸기빛 포인트 |
| **차분한 대시보드** | 청회색 바탕에 남색. 색을 줄인 업무용 |

> 별하늘·깅엄 배경은 이미지 파일이 아니라 코드로 그립니다. 화면을 키워도
> 깨지지 않고, 테마 색이 바뀌면 그대로 따라갑니다.

### 구글시트 연동

GitHub 없이 **시트만 고쳐서 검토 기준을 바꾸고**, 검토가 끝나면 **요약을 기록
시트에 남길** 수 있습니다. 구글 API 키나 로그인 연동 없이 동작합니다.

우선순위: `배포본 rules/*.yaml < 구글시트 < 앱에서 직접 수정`
(시트 = 팀 공용 기준, 앱에서의 수정 = 개인 조정)

#### 기준 시트 (읽기)

1. 구글시트를 만들고 **공유 → 링크가 있는 모든 사용자(뷰어)** 로 설정합니다.
2. 첫 시트에 아래 4열 서식으로 적습니다. 첫 행(머리글)은 있어도 되고 없어도 됩니다.

   | 종류 | 대상 | 항목 | 값 |
   |---|---|---|---|
   | 설정 | 출장비 | km_rate | 300 |
   | 설정 | 근로장학금 | max_hours_per_month | 60 |
   | 규칙 | R-TRV-008 | 등급 | 수정 필요 |
   | 규칙 | R-TRV-008 | 사용 | 아니오 |
   | 규칙 | R-CMN-002 | 조치 문구 | 최종본 1부만 남기세요 |

   - `등급` 값: 수정 필요 / 확인 요망 / 참고
   - `사용` 값: 예 / 아니오
   - `항목`: 등급 · 사용 · 제목 · 검출 문구 · 조치 문구 (규칙) / 설정 키 이름 (설정)
3. 브라우저 주소창의 시트 URL을 **설정 → 구글시트 연동**에 붙여넣고
   **지금 불러오기**를 누릅니다. 앱을 켤 때마다 자동으로도 새로 읽습니다.
4. 형식이 틀린 행은 검토를 막지 않고 "건너뛴 행"으로 알려 줍니다.
5. 오프라인이면 마지막으로 받아 둔 내용(캐시)으로 동작합니다.

#### 기록 시트 (쓰기)

검토가 끝나면 한 건당 한 행씩 남습니다:
`일시 · 지출종류 · 제출자 · 수정필요 · 확인요망 · 판독불가 · 규칙ID 목록`

**전송되는 것은 이 요약뿐입니다.** 지적 문구 원문·주민등록번호·계좌번호 같은
서류 내용은 보내지 않습니다.

받는 쪽은 기록용 시트에서 **확장 프로그램 → Apps Script** 를 열고 아래처럼
POST 로 받은 행을 시트에 붙이는 함수를 만든 뒤, **배포 → 웹 앱**
(액세스: 모든 사용자)으로 배포해 그 URL을 앱에 넣으면 됩니다.

```javascript
function doPost(e) {
  const sheet = SpreadsheetApp.getActiveSheet();
  const rows = JSON.parse(e.postData.contents).rows || [];
  rows.forEach((row) => sheet.appendRow(row));
  return ContentService.createTextOutput("ok");
}
```

**테스트 전송** 버튼으로 연결을 확인할 수 있습니다.

#### GitHub와의 관계

| 하던 일 | 시트로 대체 |
|---|---|
| 기준 한도값·등급 변경 (YAML 수정 → 커밋) | ✅ 시트 수정만으로 반영 |
| 검토 기록 남기기 | ✅ 기록 시트에 자동 축적 |
| 앱 기능(코드) 업데이트 | ❌ 코드는 GitHub 필요 — 업데이트 화면 그대로 사용 |

### 업데이트

기능이 갱신되면 여기서 받아 옵니다.

```
업데이트 확인  →  변경 내역 표시  →  업데이트 적용  →  앱 재시작
```

- **확인과 적용은 분리되어 있습니다.** 자동으로 확인만 하고, 무엇이 바뀌는지
  보여 준 뒤 사용자가 적용을 누릅니다.
- 정해진 저장소·브랜치에서만 받습니다. 다른 원격이면 중단합니다.
- 폴더에 저장하지 않은 변경이 있으면 **덮어쓰지 않고 멈춥니다.**
- 빨리감기(fast-forward)로만 갱신합니다. 되돌릴 수 없는 병합은 하지 않습니다.

시작할 때 자동 확인하는 동작은 끌 수 있습니다.

## 개인정보

- 검토는 전 과정 로컬에서 이뤄집니다. 외부로 서류를 보내지 않습니다.
- 화면과 수정 요청서에서 주민등록번호·계좌번호는 가려집니다.
- 샘플·실제 서류는 저장소에 커밋하지 않습니다(`.gitignore`).
