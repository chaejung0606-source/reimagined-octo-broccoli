# 지출 서류 자동 검토 데스크톱 앱

지출종류를 고르고 서류를 업로드하면, **기준에 따라 검토해서 수정할 부분을 정리해 알려주는** 데스크톱 앱.

대상 지출종류: **근로장학금** · **혁신인재지원금** · **출장비**

---

## 실행

```bash
pip install -e ".[gui,dev]"

# 데스크톱 앱
python -m expense_review.ui.app

# 명령줄
expense-review <폴더> --type 출장비 --batch
expense-review <폴더> --type 근로장학금 --subtype TA --roster 지급내역.pdf
expense-review <폴더> --type 혁신인재지원금 --markdown 수정요청서.md
```

`--batch` 는 하위 폴더 하나를 제출자 한 명으로 보고 한 번에 검토합니다.
`--markdown` 은 제출자에게 그대로 보낼 수 있는 수정 요청서를 저장합니다.

## 검토 기준을 고치면

앱에서 고친 기준은 **배포본을 건드리지 않고** 따로 저장됩니다.

```
rules/*.yaml          ← 배포본. 업데이트가 덮어씁니다
~/.expense-review/    ← 앱에서 고친 내용. 업데이트해도 유지됩니다
```

이렇게 나누지 않으면 담당자가 등급이나 한도를 고쳐 둔 상태에서 업데이트가 올 때
충돌이 나거나 수정 내용이 조용히 날아갑니다.

## 자동 업데이트

기능이 갱신되면 앱의 **업데이트** 화면에서 받아 옵니다.
시작할 때 자동으로 확인하고, 무엇이 바뀌는지 보여 준 뒤 적용은 사용자가 누릅니다.
정해진 저장소·브랜치에서만 받으며, 저장하지 않은 로컬 변경이 있으면 덮어쓰지 않고 멈춥니다.

## 구현 상태

OCR 없이 **텍스트 레이어에서 읽을 수 있는 범위**까지 동작합니다(1~3단계).
전체 규칙 87건 중 **64건이 자동 판정**되며, 나머지는 결과에 '미구현'으로 표시됩니다 —
조용히 통과 처리하지 않습니다.

| 단계 | 범위 | 상태 |
|---|---|---|
| 1 | 파일 분류 · L0 서류 완비성 | ✅ |
| 2 | 텍스트·표 추출 · L1 내부 계산 | ✅ |
| 3 | L2 교차 대사 | ✅ |
| 4 | OCR/Vision — 손글씨 근무일지, 스캔 영수증, 통장·신분증 | ⬜ |
| 5 | L3 한도(규정값 입력 후) · 묶음 모드 동승 중복 검출 | ⬜ |
| 6 | 규칙 편집 UI · 파일별 보기 · 자동 업데이트 | ✅ |

4단계가 필요한 항목은 판정하지 않고 **🔵 판독 불가**로 올려 사람이 확인하게 합니다.

## 코드 구조

```
src/expense_review/
  normalize.py     표기 정규화 (계좌·날짜·금액·은행·지역)
  pdfio.py         PDF 텍스트 추출 + 손상 헤더 복구 폴백
  tables.py        표 좌표 재조립 (지급내역·팀원 명단·출장자 성명)
  classify.py      서류 종류 판정 (지문 → 파일명)
  extractors/      서류별 필드 추출
  engine.py        규칙 로딩·평가·신뢰도 강등
  checks/          규칙 ID별 판정 로직
  report.py        결과 출력 + 개인정보 마스킹
  review.py        폴더 → 결과 파이프라인
  config.py        사용자 기준 오버라이드 (배포본과 분리)
  updater.py       자동 업데이트 확인·적용
  cli.py           명령줄
  ui/
    theme.py       디자인 토큰 · 스타일시트
    widgets.py     카드 · KPI 타일 · 도넛 차트
    pages/         검토 · 파일별 보완사항 · 검토 기준 · 업데이트
```

## 설계 요약

### 기준을 4개 층위로 나눈다

| Layer | 질문 | 예 |
|---|---|---|
| **L0** 서류 완비성 | 낼 게 다 왔나 | 재학증명서 누락, 교통비 증빙 블록 없음 |
| **L1** 문서 내부 정합성 | 그 서류 하나만 봐도 틀렸나 | 09:00~14:00인데 6시간, 총 이동경로 공란 |
| **L2** 문서 간 교차 정합성 | 서류끼리 말이 맞나 | 근무상황부 15h vs 지급내역 20h |
| **L3** 규정·한도 | 지침을 넘었나 | 월 근로시간 초과, 재학증명서 1개월 경과 |

### 판정은 4단계 — "위반/정상" 2분법을 쓰지 않는다

🔴 수정 필요 · 🟡 확인 요망 · 🔵 **판독 불가** · 🟢 이상 없음

손글씨 근무일지·회전된 영수증 스캔이 섞여 있어, 추출 신뢰도가 낮으면
판정 대신 **🔵 판독 불가**로 올려 사람이 확인하게 합니다. 이 장치가 없으면 오탐으로 앱을 못 씁니다.

### 지출종류별 핵심 축

| | 검토의 중심 | 가장 어려운 부분 |
|---|---|---|
| 근로장학금 | `시간 × 단가 = 금액` 삼중 대사 | 손글씨 근무일지 판독 |
| 혁신인재지원금 | 소학회명·회장·지도교수 3자 일치 | 20인 팀원표 추출, 본문에서 활동일 추출 |
| 출장비 | 영수증 ↔ 출장기간 ↔ 이동거리 | 이미지 영수증 OCR, **기간 필터 후 합산** |

### 샘플에서 실제로 검출된 문제 (규칙의 근거)

- 출장증빙의 `총 이동경로` 칸 공란 — 2명
- 교통비·이동경로 블록 자체 누락 — 3명
- 출장기간(7/3 12:00 종료) **밖**의 통행료 영수증(7/3 13:20) — 1명
- 체류 증빙 일자 누락 — 1명
- 활동보고서 활동일(5/4·5/18)과 근무상황부 근로일(5/6·5/13·5/20) 불일치
- 팀원 학번 8자리(9자리여야 함)
- 계좌번호 표기 형식 차이 → **정규화하면 정상** (오탐 방지 사례)

4. 동승 중복청구 처리 원칙
5. 반려 기준선 — 🔴 1건이면 반려인지, 담당자 재량인지
